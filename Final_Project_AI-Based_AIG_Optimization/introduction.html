利用 AI 与逻辑综合工具优化 AIG

面向 IWLS 2026 benchmark 的方法介绍

1. 什么是 AIG

AIG 是 And-Inverter Graph。

它只使用两类基本结构：

  • AND 节点
  • 边上的取反标记

一个组合逻辑电路可以被表示成 AIG。优化 AIG 的目标通常有两个：

  • 降低逻辑层数，也就是 delay
  • 减少 AND 节点数，也就是 area

这两个目标经常互相冲突，所以我们通常保留一组 Pareto 解，而不是只保留一个电路。

2. 这次任务的优化目标

我们面对的是 100 个 combinational truth-table benchmark，编号为 ex200 到 ex299。

每个 benchmark 给出完整 truth table。我们的目标是：

  1. 生成和 truth table 等价的 AIG。
  2. 尽可能降低 level。
  3. 尽可能减少 AND 节点数。
  4. 在 level 和 area 之间保留多个 tradeoff。

最终比较指标：

指标 含义 越小越好
Level AIG 的最长逻辑路径层数 Yes
Area AIG 中 AND 节点数量 Yes

3. 总体思路

我们的优化不是单一工具完成的，而是一个组合流程。

核心思想：

  1. 用 AI 辅助理解 truth table 背后的函数结构。
  2. 把可识别的函数写成更高层次的 Verilog。
  3. 用 Yosys 把 Verilog 综合成初始 AIG。
  4. 用 ABC、ABC9、MockTurtle、CULS 继续优化 AIG。
  5. 保留所有 non-dominated Pareto 点。
  6. 对每个候选结果做等价性验证。

可以理解成两层优化：

  • 前端：尽量生成“结构更好”的电路描述。
  • 后端：对已有 AIG 做局部重写和全局搜索。

4. 为什么需要 AI

如果直接从 truth table 生成 AIG，电路通常非常大。

AI 在这里主要用于 reverse engineering：

  • 观察 truth table 的输入输出规律。
  • 猜测 benchmark 对应的数学函数。
  • 生成可读的 Verilog 实现。
  • 提出不同的分解方式。
  • 针对失败 case 继续尝试新结构。

AI 不直接替代验证。所有 AI 生成的 RTL 和 AIG 都必须经过 exhaustive simulation 或 CEC 检查。

5. AI 能发现什么

对这些 benchmark，AI 辅助发现了几类结构：

Case 范围 识别出的结构
ex200-ex219 BF16 unary functions
ex220-ex239 FP16 unary functions
ex240-ex254 float conversion 和 fp8 add
ex255-ex279 整数乘法、除法、平方、平方根
ex280-ex299 未命名函数，但有 class、rotation、split 等结构

一旦从“随机 truth table”变成“有语义的函数”，优化空间会大很多。

6. 方法一：从 truth table 直接生成 AIG

这是最基础的 baseline 方法。

做法：

  1. 读取 truth table。
  2. 直接构造等价逻辑。
  3. 得到初始 AIG。
  4. 再用综合工具优化。

优点：

  • 一定可以得到等价电路。
  • 自动化程度高。

缺点：

  • 难以利用函数本身的结构。
  • 面积经常很大。
  • 对 16-bit 输入、16-bit 输出的复杂函数尤其不友好。

7. 方法二：AI reverse engineering + Verilog

更有效的方法是先理解函数，再写结构化 Verilog。

例子：

  • 如果发现是 sqrt(x)，就不要用完整 truth table。
  • 可以写成 exponent 处理 + mantissa lookup table。
  • 如果发现是整数乘法，就直接写乘法结构。
  • 如果发现输出有对称性，就只实现一半逻辑。

这种方法的本质是：

用更高层级的语义，替代低层级的 truth table 展开。

8. 浮点函数优化

很多 benchmark 是浮点函数，包括：

  • exp
  • log
  • sin
  • tan
  • sqrt
  • reciprocal
  • cube root
  • sigmoid

我们使用的浮点假设：

  • DAZ：denormal input 视为 zero
  • FTZ：denormal output flush to zero
  • RNE：round to nearest even
  • canonical NaN

关键优化手段：

  • 分离 sign、exponent、mantissa。
  • 对 mantissa 使用小规模 lookup table。
  • 对 exponent 使用整数加减、移位、比较。
  • 对奇函数使用 odd symmetry。
  • 对饱和区间直接输出 constant。
  • 对 passthrough 区间避免复杂计算。

9. BF16 的特点

BF16 的 mantissa 只有 7 bit。

这意味着很多函数只需要 128-entry lookup table 就可以精确表示 mantissa 变换。

典型结构：

  1. 拆出 sign、exponent、mantissa。
  2. 对 exponent 做区间判断。
  3. 对 mantissa 查表。
  4. 做 rounding。
  5. 重新组装 BF16 输出。

这种结构比直接 truth table 小很多。

10. FP16 的特点

FP16 的 mantissa 是 10 bit。

直接查表需要 1024 entries，比 BF16 大，但仍然比完整 truth table 好很多。

有效方法：

  • 按 sign 和 exponent 分组。
  • 很多 exponent 区间是 constant、zero、inf 或 passthrough。
  • 只有少数区间需要 mantissa table。
  • 对每个区间单独生成更简单的 case 结构。

这类结构再交给 Yosys 和 ABC 后端，通常可以得到稳定的改进。

11. 整数算术函数优化

部分 benchmark 对应整数算术：

  • unsigned multiplication
  • signed multiplication
  • unsigned division
  • square
  • integer square root

这类函数适合直接写成算法 RTL。

例如：

  • 乘法用乘法表达式。
  • 除法加入 divide-by-zero saturation。
  • 平方用共享输入乘法。
  • 整数平方根用 restoring sqrt。

综合器可以识别这些结构，并生成远小于 truth table 的 AIG。

12. 未知函数的处理

ex280-ex299 这组函数没有完全命名。

对这类 case，我们使用结构搜索：

  • 按输入高位或低位分组。
  • 尝试 class-based factoring。
  • 尝试 rotation canonical form。
  • 从 truth table 自动生成 split RTL。
  • 用 decision graph 学习可分解结构。

这类方法不一定能解释函数语义，但能找到更适合综合的表示。

13. Yosys 的角色

Yosys 是 RTL 到门级/AIG 的前端综合工具。

在我们的流程中，Yosys 负责：

  1. 读取 Verilog。
  2. 做过程块展开、表达式优化、常量传播。
  3. 对 case、比较器、算术结构做综合。
  4. 生成初始 AIG。

Yosys 很重要，因为 AI 生成的是 Verilog，而最终提交需要的是 AIG。

一个好的 Verilog 结构，经过 Yosys 后往往能得到比 truth table baseline 小很多的初始 AIG。

14. ABC 的角色

ABC 是主要的 AIG 优化后端。

常用操作包括：

  • rewriting
  • refactoring
  • balancing
  • resubstitution
  • strashing
  • mapping-aware optimization
  • deep synthesis

ABC 的作用：

  • 降低 level。
  • 减少 AND 节点。
  • 在已有 AIG 上做大量局部等价变换。
  • 通过随机命令序列探索不同优化路线。

15. ABC9 的角色

ABC9 是 ABC 中更现代的优化和 mapping 相关流程。

它对某些 case 的低 level 优化特别有帮助。

我们把 ABC9 当作 portfolio 的一部分：

  • 有些 case ABC 普通流程更好。
  • 有些 case ABC9 更好。
  • 两者都跑，然后保留 Pareto 最优点。

这也是整个项目的基本策略：不要依赖单一工具，而是让多个工具竞争。

16. MockTurtle 的角色

MockTurtle 提供了另一套逻辑网络优化算法。

常用 pass：

  • cut rewriting
  • window rewriting
  • refactoring
  • resubstitution
  • simulation-guided resubstitution

MockTurtle 的价值在于：

  • 搜索空间和 ABC 不完全相同。
  • 某些 AIG 在 ABC 中停滞后，MockTurtle 还能找到新结构。
  • 和 ABC 交替使用时，经常能产生新的 Pareto 点。

17. CULS 的角色

CULS 是 GPU 加速逻辑综合工具。

常用操作：

  • rewriting
  • refactoring
  • resubstitution
  • balancing
  • strashing

CULS 的主要价值：

  • 利用 GPU 加速大规模局部搜索。
  • 对大 AIG 可以快速尝试更多变换。
  • 作为 ABC 和 MockTurtle 之外的第三种后端。

在 portfolio 中，CULS 不一定每个 case 都赢，但它能扩展搜索空间。

18. Portfolio 优化思想

我们最终采用 portfolio，而不是单一路线。

每个 case 同时尝试：

  • truth-table baseline
  • AI-generated word-level RTL
  • Yosys synthesis
  • ABC optimization
  • ABC9 optimization
  • MockTurtle optimization
  • CULS optimization
  • decision-graph decomposition

每条路线都可能产生不同 tradeoff。

最后统一做：

  1. 等价性验证。
  2. level/area 统计。
  3. Pareto pruning。
  4. 保留 non-dominated points。

19. Pareto front 是什么

如果一个 AIG 的 level 和 area 都不比另一个 AIG 好，那么它就是 dominated，可以删除。

例如：

AIG Level Area
A 10 1000
B 12 900
C 12 1100

这里 C 被 A 和 B 支配：

  • A 的 level 更低，area 也更低。
  • B 的 level 相同，area 更低。

所以 C 没有保留价值。

20. 等价性验证

优化电路时，最重要的是不能改变功能。

我们使用两类验证：

  1. RTL exhaustive simulation
    对 AI 生成的 Verilog，逐个输入枚举，检查输出是否等于 truth table。

  2. AIG CEC
    对最终 AIG，和 truth table 构造出的参考电路做 combinational equivalence checking。

只有验证通过的结果才会进入最终统计。

21. 一个典型优化流程

以一个浮点函数 case 为例：

  1. 先从 truth table 生成 baseline AIG。
  2. 用 AI 分析输入输出模式，猜测它是某个 BF16/FP16 函数。
  3. 写出结构化 Verilog。
  4. exhaustive simulation 验证 Verilog。
  5. 用 Yosys 综合成 AIG。
  6. 用 ABC、ABC9、MockTurtle、CULS 做后端优化。
  7. 对所有 AIG 做 CEC。
  8. 保留 Pareto front。

这个过程可以反复迭代：后端卡住时，回到前端重新设计 Verilog 结构。

22. 关键经验

一些对结果影响很大的细节：

  • truth table indexing 和 Verilog 输入顺序必须严格对应。
  • RNE rounding 的 carry 必须传播到 exponent。
  • 浮点 NaN、inf、zero、subnormal 的 corner case 必须单独处理。
  • BF16 适合小 mantissa LUT。
  • FP16 适合按 exponent 分组后局部查表。
  • 奇函数可以使用 sign symmetry。
  • 未知函数不一定要完全命名，能找到可综合分解也有价值。
  • 后端工具之间要交替使用，单一工具很容易到局部最优。

26. 总结

这次 AIG 优化的核心经验是：

AIG 后端优化很重要，但更大的提升往往来自前端结构发现。

AI 的作用是帮助我们从 truth table 中恢复语义和结构；Yosys 把这些结构转成可优化的 AIG；ABC、ABC9、MockTurtle 和 CULS 负责在 AIG 层面继续压缩。

最终形成的有效路线：

  1. AI 辅助 reverse engineering。
  2. 结构化 Verilog 生成。
  3. Yosys 前端综合。
  4. ABC / ABC9 / MockTurtle / CULS portfolio 优化。
  5. CEC 验证。
  6. Pareto front 保留。

在当前结果中，100 个 case 的 best-area 和 best-level 都优于 baseline，平均面积改进 37.72x，平均 level 改进 2.73x。
